# Sarah Telegram Bot

Python 3.11+, aiogram 3, асинхронный OpenAI Responses API, Firebase Realtime Database.

## Запуск

```sh
python3.11 -m venv .venv
.venv/bin/python -m pip install --no-cache-dir -r requirements.txt
cp .env.example .env
chmod 600 .env
# Заполните OPENAI_API_KEY проектным ключом и TELEGRAM_BOT_TOKEN.
.venv/bin/python bot.py
```

Секреты из `bot_token.py`, `consts/access_keys.py`, `consts/database_url.py` и список
администраторов из `consts/admins.py` поддерживаются для совместимости. Переменные
окружения имеют приоритет, затем `.env`, затем старые файлы. Старый organization header
не наследуется: проектный ключ определяет проект, при необходимости задайте
`OPENAI_PROJECT` и `OPENAI_ORGANIZATION` явно. Ключи и Firebase credentials в git не добавлять.
Перед заменой ключа создайте Project API key в https://platform.openai.com/api-keys.
Старый ключ отзывайте после успешной проверки и перезапуска новой версии.

## Модели и баланс

| Режим | Модель | Токенов бота за ответ | Старое значение |
|---|---|---:|---|
| Быстрый | gpt-6-luna | 1 | gpt3 |
| Умный | gpt-6.1-terra | 4 | gpt4 |
| Изображение | gpt-image-2.5-flare, low, 1024×1024 | 10 | /image |

Модели и цены проверены по официальной документации 29.10.2026:
[каталог](https://developers.openai.com/api/docs/models),
[цены](https://developers.openai.com/api/docs/pricing).
Для текста Standard за 1 млн входных/выходных токенов: Luna $0.10/$0.50,
Terra $1/$5. Это токены API, не токены внутреннего кошелька.
Фактическая стоимость зависит от длины истории, ответа и reasoning.
История ограничена 24 сообщениями и 24 000 символами, ввод — 12 000 символов.
Перед генерацией весь вход вместе с инструкциями, фото и историей проверяется через
Responses input_tokens.count: не более 8192 API-токенов. Старые полные пары сообщений
убираются из запроса до попадания в лимит; слишком большой текущий вопрос отклоняется
без платной генерации. Ответ — до 1536 токенов, включая reasoning.
Для изображений фиксированы количество, размер и качество; запрос до 3000 символов.
Скрытых переключений на дорогие модели и платного веб-поиска нет.
GPT-6.1 Sol проверен, но новый проект возвращает для него `403 model_not_found`.
Он не предлагается пользователям. Прежний режим GPT-4 переведён на доступную Terra:
стоимость уменьшена с 12 до 4 токенов бота. Включать недоступный Sol для запуска не требуется.

Пути `users/{id}`, `contexts/{id}`, `payments/{id}` сохранены. Существующие остатки,
даты регистрации, история платежей и неизвестные поля сохраняются. Модель переводится
при следующем обращении пользователя, без общей перезаписи базы. Старые названия моделей
сохраняются только в обработке исторических настроек, не в командах бота.
Выбор моделей: `/luna`, `/terra`, `/models`. Команды старых моделей удалены.
Команды диалога: `/new`, `/reset`, `/retry`, `/stop`, `/style`, `/export`, `/help`.
Баланс, приглашения и помощь: `/tokens`, `/ref`, `/image`, `/buy`, `/users`, `/support`.
Бот работает в личных чатах; история не разделяется с участниками групп.

Сначала транзакционно резервируется стоимость запроса. Отмена до отправки OpenAI
бесплатна. После отправки стоимость запроса списывается, включая `/stop`, сетевой сбой
с неизвестным результатом и сбой доставки Telegram. Явный отказ API до обработки
возвращает пользователю кредиты. Полный сгенерированный текст сохраняется до окончательной
отправки и доступен через `/export`, если отправка сообщения не удалась.
Перед обращением к API в Firebase и финансовом журнале сохраняется стадия обработки.
После перезапуска незапущенные запросы возвращаются, отправленные с неизвестным исходом
считаются использованными. Повторный Telegram message ID не оплачивается повторно.
Старый процесс должен быть остановлен перед запуском нового.
Квитанции оплат и реферальные начисления идемпотентны в транзакции пользователя.

Один пользователь генерирует один ответ одновременно; другие чаты обслуживаются независимо.
Глобальный предел — `MAX_CONCURRENT_REQUESTS=4`, дедлайн — `REQUEST_TIMEOUT=120` секунд
плюс до 60 секунд на очередь и отправку. Фото передаются в low-detail и не сохраняются
в истории; последующие сообщения видят текст запроса и ответ, но не исходное фото.
Для `/retry` после фото бот попросит отправить фото заново, без списания токенов.
`/export` выгружает текущую сохранённую историю; `/new` очищает её.
Ответы отправляются без HTML-разбора и делятся по лимиту Telegram, включая emoji.
Администратор может вызвать `/public` или `/public текст`, проверить предпросмотр
и подтвердить рассылку кнопкой. Случайное сообщение не отправляется всем пользователям.
Предпросмотр действует 10 минут, повторное подтверждение не запускает вторую рассылку;
`/cancel` останавливает отправку. Массовые сообщения не запускаются при обновлении бота.

## Платежи

Новые покупки используют [Telegram Stars](https://core.telegram.org/bots/payments-stars)
с валютой XTR. Владелец задаёт `STARS_PACKAGES` в `.env`, например
`STARS_PACKAGES={"110":99,"570":499,"1200":999,"6300":4999}`.
Для этого обновления владелец одобрил пересчёт с округлением вверх: пакеты
110 / 570 / 1200 / 6300 токенов стоят 99 / 499 / 999 / 4999 Stars.
Основа — эквивалент выручки владельца: прежние 100 / 500 / 1000 / 5000 RUB,
[курс ЦБ 29.10.2026](https://www.cbr.ru/currency_base/daily/?UniDbQuery.Posted=True&UniDbQuery.To=29.10.2026)
80.8664 RUB/USD и [вознаграждение Telegram](https://telegram.org/tos/bot-developers#6-2-4-rewards-for-stars)
$0.013 за Star. Исходные величины 95.12 / 475.62 / 951.24 / 4756.18 Stars
округлены вверх. Это эквивалент дохода, а не единая цена покупки Stars пользователем.
Цена приобретения Stars зависит от региона и платформы. Тарифы фиксированы в `.env`;
автоматической переоценки по курсу нет.
Без этой настройки новые продажи приостановлены; существующие токены и рефералы работают.
Старые успешные RUB-платежи с payload `real-invoice-live` и известной суммой принимаются,
новые оплаты по устаревшим счетам отклоняются с предложением создать новый.
Проверяются валюта, сумма, payload и владелец нового счёта; квитанция и пополнение
проводятся одной транзакцией, чтобы повторный update не начислял деньги дважды.
`refunded_payment` отменяет покупку ровно один раз, в том числе если уведомление пришло
до `successful_payment`. Повторная доставка успешной оплаты после возврата не начисляет
кредиты. Если покупка уже потрачена, сохраняется отрицательный баланс, и новые запросы
недоступны до его покрытия. Реферальное начисление сверяется с состоянием покупки в одной
Firebase-транзакции; при отмене последней покупки неиспользованный бонус отзывается.
Возвраты дополнительно сверяются с полной историей Stars при запуске и каждые 30 минут.
Если сверка завершается ошибкой или её результат старше часа, генерации приостанавливаются
до успешной проверки; баланс пользователя за отклонённый запрос восстанавливается.
Укажите `SUPPORT_USERNAME` для `/support` и `/paysupport`; иначе используется первый ADMIN_IDS.

## Защита расходов

`data/finance.sqlite3` — закрытый локальный журнал расходов, резервов и бонусов.
SQLite BEGIN IMMEDIATE не позволяет параллельным запросам занять один бюджет дважды.
Каталог исключён из Git. Данные и WAL-файлы не удалять при обновлении; перед переносом
на другой сервер переносите журнал вместе с резервной копией приложения.
Для согласованной копии остановите службу; backup.py сохраняет каталог data.
Если указали FINANCE_DB_PATH вне рабочей папки, копируйте этот файл отдельно.

Лимиты по умолчанию: `$20` API в месяц, `$2` в день, внутри них `$1` в месяц на новые
бонусы. Переменные: MONTHLY_API_BUDGET_USD, DAILY_API_BUDGET_USD,
PROMO_MONTHLY_BUDGET_USD; нулевой бюджет запрещает новые запросы соответствующей категории.
Периоды считаются в Asia/Tbilisi. Лимиты действуют также для администратора и близких.
Перед каждым запросом резервируется консервативный максимум: Luna $0.001792,
Terra $0.01792, изображение $0.08. После ответа резерв заменяется стоимостью из usage,
включая cache reads/writes и reasoning в общем output_tokens. При потере usage после
отправки сохраняется полный резерв. Ошибки 400/422, в том числе выходная модерация,
не обнуляют неизвестную себестоимость. Автоповторы платных запросов отключены.
Если измеренная цена превышает резерв, новые генерации приостанавливаются до проверки.
Это ограничение расходов данного приложения по указанной книге цен, а не административный
лимит всего аккаунта OpenAI; ручные диагностические вызовы API вне маршрута бота в него
не входят. При изменении цен провайдера обновите services/pricing.py и резервы.

Новые бонусы: 25 токенов на регистрацию, 15 пригласившему после первой покупки друга.
Уже существующие балансы не переводятся в бонусные и продолжают работать на всех моделях.
Новые бонусы хранятся отдельной частью общего остатка и расходуются только на Luna,
до 5 запросов в день. Купленные и существующие кредиты расходуются первыми.
Выдача бонусов ограничена 250 кредитами в день и 2500 в месяц; невыданный приветственный
бонус остаётся ожидающим и может быть получен при следующем обращении после освобождения
лимита. Реферальные начисления также повторяются безопасно после временного сбоя.
Для всех пользователей: до 100 запросов в сутки и интервал не менее 2 секунд.
Отмены и отклонённые после резервирования попытки тоже учитываются в частотном лимите.

`/finance` доступна только администраторам: расходы, лимиты и число активных резервов.
PERSONAL_USER_IDS в .env отделяет личное использование от продаж в журнале; администраторы
также относятся к personal. Промо всегда учитывается в собственном ограниченном бюджете.
Команда `python scripts/finance_report.py` выдаёт агрегированный отчёт без ключей,
переписок и идентификаторов пользователей. Журнал начинает учёт с установки этой версии;
прошлые расходы OpenAI автоматически не восстанавливаются.

## Сервер и резервные копии

Рабочая папка: `/home/SarahGPTBot`, служба: `sarah_gpt_bot.service`.
Юнит: `deploy/sarah_gpt_bot.service`. Он запускает Python напрямую, а не shell-процесс,
корректно завершает запросы и пишет ограниченный systemd journal.
При обновлении нельзя удалять очередь Telegram (`drop_pending_updates=False`).
Старое `venv` оставлено для аварийного отката; новая версия использует `.venv`.

```sh
.venv/bin/python scripts/backup.py
systemctl status sarah_gpt_bot.service
journalctl -u sarah_gpt_bot.service -n 50 --no-pager
df -h /
```

`backups/<UTC timestamp>/application.tar.gz` содержит код/конфигурацию;
`firebase.json` — users, contexts, payments, payment_orders. Доступ только владельцу.
Для согласованного снимка остановите службу перед backup. Копии содержат секреты и личные данные:
не публикуйте их. Восстанавливайте Firebase только при реальном повреждении данных,
иначе затрутся новые платежи. Для отката кода остановите службу, распакуйте архив приложения,
восстановите предыдущий systemd unit и запустите старое окружение. Старые модели уже
недоступны, поэтому предпочтителен откат с исправлением конкретной проблемы в новой версии.

Очистка сервера 29.10.2026: удалены кэши pip/apt и старые ротации системных журналов,
текущие журналы сжаты. Journald ограничен 64 МБ с резервом 512 МБ, rsyslog ротируется
ежедневно, с порогом 10 МБ при запуске logrotate, без задержки сжатия.
Другие боты и их данные не удалялись.

## Обновления через GitHub

Основной процесс: изменения, проверки, commit и push выполняются локально;
сервер получает тот же коммит через `git pull --ff-only`. Репозиторий:
`git@github.com:enotgr/SarahGPTBot.git`, ветка `master`.
Не редактируйте рабочий код на сервере вручную. `.env`, ключи, Firebase credentials,
резервные копии и `.upgrade` не входят в Git и сохраняются при pull.

Перед обновлением проверьте `git status --short`: неожиданные изменения нужно
сохранить и разобрать, а не затирать. Для обновления на сервере:

```sh
cd /home/SarahGPTBot
git fetch origin
systemctl stop sarah_gpt_bot.service
.venv/bin/python scripts/backup.py
git pull --ff-only
.venv/bin/python -m pip install --no-cache-dir -r requirements.txt
.venv/bin/python -m pip check
systemctl start sarah_gpt_bot.service
systemctl status sarah_gpt_bot.service --no-pager
```

После запуска сравните `git rev-parse HEAD` локально и на сервере и проверьте
`journalctl -u sarah_gpt_bot.service -n 30 --no-pager`. Если проверка или установка
зависимостей завершилась ошибкой, устраните её перед запуском службы.
